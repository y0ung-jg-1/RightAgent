# Acceptance test matrix

## Automated gates

- Managed tests: defaults detect commands, including Cursor Agent's exact `cursor-agent` command; Windows Terminal detection covers PATH/WindowsApps/missing cases; Terminal profile catalogs parse JSONC `defaultProfile` and visible/hidden profiles from both object and legacy array shapes; menu-mode values normalize safely, IDs/order/direct target are repaired, URL schemes are restricted, Unicode settings save/load atomically, `install.json` writes atomically, occupancy add/remove plans match the required slot prefix, built-in icon keys are allowlisted, and Windows can thumbnail `testdata/icon.svg`.
- Shared normalize golden file: `testdata/normalize-agents.json` is a `scenarios` array; each entry carries a full `input` settings document and the complete `expected` normalized document. The managed suite compares `SettingsValidator.Normalize` output with `JsonNode.DeepEquals`, and the native suite parses each input through `LoadSettingsFromPath` and verifies every field, so adding coverage means editing JSON only — no per-side assertion lists. Scenarios pin id/name/icon/URL/menu-mode/language/sort/direct-target repairs on both sides, including the aligned drive-letter icon rejection, empty `local:` icon fallback, `terminalProfile` trimming, missing-sort default, the `http://`/`https://` authority prefix rule, and URLs that fail an absolute URI parse (`:99999`, unclosed IPv6).
- Command-package occupancy synchronization: `RightAgent.Core`'s `CommandPackageSynchronizer` orchestration (identity resolution through `install.json`, list/plan/apply under the installation mutex, stamp file gating, add/remove order, mutex timeout and failure release, shell-change notification, overlapping runs with different required slot counts) is covered by `CommandPackageSynchronizerTests` against a fake `ICommandPackageDeployment` and real temp directories. No-op occupancy takes the mutex; contended no-ops return `Skipped`. Still untested: `WindowsCommandPackageDeployment`'s real `PackageManager` deployment calls, the 30-second `WaitForDeployment` timeout (would need a fake `IAsyncOperationWithProgress`), and `FindInstalledCommandSlots`'s per-slot error swallowing against a live deployment service.
- View-model tests (`RightAgent.App.Tests`): an xunit host referencing the WinUI app project directly (PRI generation disabled, the app's `RightAgent.App.pri` resolved from the App project output and required at copy time, occupancy sync injected as a delegate, Windows Terminal catalog stubbed to `Empty`). Covered: a flush with an invalid field keeps the disk settings and skips occupancy (the bypass-fixed contract "sync only after a valid persist"), a valid flush syncs exactly the persisted snapshot, a persist-side direct-target repair no longer re-schedules a debounced save (the self-cancel regression), that repair is marshaled through exactly one `Post` on a context captured at construction (a blocking `Send` fails the test), an invalid keystroke cancels a pending debounce so the disk is not written, and overlapping occupancy runs apply the latest persisted snapshot. Still untested: XAML pages, `MainWindow` lifecycle, a real `DispatcherQueue` / `PackageManager`, and persist-side stale repairs.
- Native tests: Windows argument round-trip covers spaces, Chinese, parentheses, single quotes, ampersands, quotes, and trailing backslashes; icon resolution, the unpackaged settings fallback, explicit settings-path overrides, legacy-key tolerance (a leftover `terminalShell` value is ignored), Windows Terminal `defaultProfile` parsing (including JSONC comments), profile-shell classification / `--appendCommandLine` tokens, and every `testdata/normalize-agents.json` scenario's id/name/icon/URL repairs (field-for-field, matching the managed writer) are verified. Built-in agent defaults and command detection are a managed-only contract (`SettingsDefaults` / `CommandLocator`); native code no longer keeps a second copy of the default table — it only probes PATH to validate a launch (`CommandExists`).
- Native COM smoke test: loads `RightAgent.Shell.dll` without registration, checks grouped and single-direct behavior, then verifies 16 registered class slots, ordered multi-direct root titles/actions, hidden unused slots that refuse a title and icon, and main-package family mapping. Manifest validation requires one independently identified hidden command package per slot so Explorer cannot collapse multi-direct commands into one app-attributed flyout. Managed tests cover how many command packages each menu mode should leave installed.
- Release build: x64 Launcher and Shell compile with warnings as errors; WAP produces one unsigned settings package and the command packer produces 16 unsigned hidden command packages before signing.
- Release installer: ordinary CI builds unsigned command packages and an unsigned per-machine Setup.exe (plus a compiled UserSetup SKU). The public Release uploads only the signed Setup.exe plus its SHA-256. The tag workflow runs the per-machine Setup quietly on its clean hosted runner and rejects installer exceptions, a missing unpackaged settings app under Program Files, a missing Start-menu shortcut to that app, a missing or wrong command-package version, command packages exposed in Start, or an incorrect certificate store.

## Manual Windows 11 acceptance

1. On a clean account, double-click the per-machine Setup.exe and approve UAC. Confirm the wizard follows the Windows display language, the unpackaged settings app lands in `%ProgramFiles%\RightAgent`, and the command packages required by the current settings deploy (slot zero on a clean machine; unused slots stay unregistered and all 16 command MSIX files are cached under `%LOCALAPPDATA%\RightAgent\CommandPackages`). Confirm the certificate exists only in Local Machine\Trusted People, not Trusted Root; cancelling UAC must leave the app uninstalled.
2. While installation is active, start the same Setup again and confirm the second instance is rejected. After installation, run the same Setup version again and confirm it succeeds without resetting `%LOCALAPPDATA%\RightAgent\settings.json`.
3. Open RightAgent once. With Windows Terminal installed, confirm no dependency prompt appears. With `wt.exe` unavailable, confirm a localized prompt offers **Open Microsoft Store** and **Later**; Later keeps the settings app usable and the prompt returns after reopening.
4. Open the settings window at its default size on 100%, 150%, 175%, and 200% display scaling. Confirm the default size is DPI-aware (1109×698 DIP, not a locked physical pixel size), the window is centered on the current monitor work area, and the live preview is visible whenever the content area can fit the settings column and the preview. Resize down to the enforced minimum and confirm the preview disappears only when that pair no longer fits, setting cards keep header and action on one row until the row is actually full, unused width goes to the settings column or the preview rather than an empty gap, and vertical scrolling still reaches the final field.
5. Right-click a folder background and confirm the command is in the modern menu, not only under `Show more options`.
6. Right-click one selected folder and confirm the same behavior.
7. Confirm no command appears for files, multiple selected folders, This PC, Libraries, ZIP virtual folders, or non-file-system locations.
8. Test grouped, single-direct, and multi-direct modes; toggle, rename, reorder, add, delete, and change the direct agent. Confirm a saved setting is read from `%LOCALAPPDATA%\RightAgent\settings.json` by every COM surrogate. After saving, only the command packages required by the current mode stay installed (one for grouped/direct, one per enabled agent for multi-direct). In multi-direct mode, confirm every enabled agent appears independently at the menu root in configured order, no `RightAgent` wrapper or flyout remains, disabled agents stay hidden, Explorer does not flash leftover "Loading..." placeholders for unused slots, and more than 16 enabled agents cannot be saved.
9. Verify Chinese, English, and system language, including menu title and launcher errors.
10. With Windows Terminal profile set to **Use Terminal default**, launch an agent. Confirm the new tab uses that Startup default profile's shell and icon (the same as clicking Terminal's **+**). If the default is PowerShell, run `$PSVersionTable.PSVersion` and confirm it matches opening that profile by hand.
11. Pick Command Prompt, Git Bash, and a Developer Command Prompt profile if present; launch an agent in each and confirm the tab keeps that profile's own shell. Verify the working directory with `cd` or `pwd`.
12. Launch `claude`, `codex`, `kimi`, and `cursor-agent`; confirm each new Terminal window uses the exact selected folder.
13. Repeat with a folder named `中文 space & (test) 'quote'`.
14. Configure an `https` web action and confirm the default browser opens. Confirm `file:`, `javascript:`, and malformed URLs cannot be saved as enabled actions.
15. Temporarily configure a missing simple command and confirm the launcher error offers **Open settings** without crashing Explorer.
16. Test light, dark, and high-contrast themes; keyboard-only navigation; Narrator labels; and text scaling.
17. Close the settings app and complete a menu launch. Confirm Task Manager has no remaining RightAgent process after the launcher returns.
18. Install `0.1.0.0`, install a higher version over it, then uninstall RightAgent from Apps & features. Confirm the upgrade kept `%LOCALAPPDATA%\RightAgent\settings.json`. After uninstall, confirm no `RightAgent.Command*` Appx packages remain, `%ProgramFiles%\RightAgent` (or the per-user Programs folder) is gone, `%LOCALAPPDATA%\RightAgent` is gone, the RightAgent certificate is absent from Local Machine\Trusted People, and no modern context-menu command remains visible without signing out.

Setup and the settings app must not terminate `explorer.exe`. If a folder window still shows a stale command after occupancy changes, close that window or sign out once. Do not add a background watcher merely to refresh the menu.
